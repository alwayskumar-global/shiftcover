Accessibility decisions per screen

Focus order, touch targets and reduced-motion behavior per screen, then the contrast pairs actually used. Ratios are computed live from tokens.css when this page loads, so they cannot drift from the tokens. Items marked Not built are gaps in the prototype that the implementation must add.

Global rules

  • Status is never colour alone: every badge, block, node and alert has an icon and a word. Unfilled and Cancelled also use dashed outlines; Open gap is the only hatched block.
  • One focus style everywhere: 2px surface gap plus 2px blue ring (--sc-ring-focus), on :focus-visible.
  • Worker app: every tap target at least 48px; primary actions 56px. Body text at least 16px.
  • Console: controls 40px; body prose at least 14px; captions 12px.
  • Errors have an icon, text, role="alert", and are tied to the field with aria-describedby. They are never only a red border.
  • Buttons that are busy use aria-disabled (not disabled) so focus stays put, and the label changes ("Claiming…").
  • Reduced motion: prefers-reduced-motion: reduce stops all keyframe animation and zeroes durations. State is carried by words, never by motion.
  • Times are announced with relative text plus a title or visible clock time.
  • Not built A skip link ("Skip to main content") before the console nav.
